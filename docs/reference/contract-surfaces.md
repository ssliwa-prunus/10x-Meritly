## Policy conventions

- Role checks in policies call the helpers wrapped in a sub-select, e.g. `using ((select public.is_admin()))`, so Postgres evaluates them once per statement. Never sub-select `public.profiles` inline in a policy (it recurses into the profiles policies).
- Enable RLS in the migration that creates the table, with one policy per operation per role and no `for all` policies.
- Views over RLS-protected tables are created with `security_invoker = true`.
- Structural RLS tests (pgTAP) live in `supabase/tests/` and run in CI via `supabase test db`.

## Config snapshot rule

- Computations read `public.bonus_settings` and `public.job_roles` at compute time; the config itself is not versioned.
- S-04/S-05 result rows must persist the role weight, rating factor, milestone multiplier and bonus they used, so later config edits never change Approved milestones.
- Archived job roles stay readable (existing references keep resolving). New assignments must pick only rows with `archived_at is null`.
