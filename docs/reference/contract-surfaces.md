# Contract surfaces

Load-bearing names that later slices must reuse and must not rename. Changing any of these is a breaking change across migrations, policies, tests and app code.

## Registry

| Name                        | Kind                                                       | Defined in                                                     | Contract                                                                                                                                                                                                                                                                                                                                  |
| --------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `public.app_role`           | Postgres enum                                              | `supabase/migrations/20260925120000_role_and_rls_scaffold.sql` | Values `admin`, `supervisor`, `employee`.                                                                                                                                                                                                                                                                                                 |
| `public.profiles`           | Table                                                      | same migration                                                 | One row per `auth.users` row. Columns: `id` (uuid, PK, FK `auth.users.id` on delete cascade), `email` (text, not null), `display_name` (text, nullable), `role` (`public.app_role`, not null, default `employee`), `created_at` (timestamptz, not null, default `now()`). RLS enabled; anon has no privileges; no insert/delete policies. |
| `public.current_app_role()` | SQL function, security definer                             | same migration                                                 | Returns the caller's `app_role` (null when no profile). Executable by `authenticated` only.                                                                                                                                                                                                                                               |

Executable by `authenticated` only.                                                                                                                                                                                                                                                   |
| `public.is_supervisor()`    | SQL function, security definer                             | same migration                                                 | True when the caller's role is `supervisor`, else false. | `on_auth_user_created`      | Trigger on `auth.users` (calls `public.handle_new_user()`) | same migration                                                 | Creates an `employee` profile for every new auth user; never reads the role from user metadata.                                                                                                                                                                                                                                           |

## Policy conventions

- Role checks in policies call the helpers wrapped in a sub-select, e.g. `using ((select public.is_admin()))`, so Postgres evaluates them once per statement. Never sub-select `public.profiles` inline in a policy (it recurses into the profiles policies).
- Enable RLS in the migration that creates the table, with one policy per operation per role and no `for all` policies.
- Views over RLS-protected tables are created with `security_invoker = true`.
- Structural RLS tests (pgTAP) live in `supabase/tests/` and run in CI via `supabase test db`.
