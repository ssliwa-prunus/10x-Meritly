### Czego NIE zweryfikowano (ograniczenia)

- `Model_premiowania.xlsx` — nie otwierano (binarny). Fakty o arkuszu (`MIN(M,1)`, `1 - R/100`, zakładki Wyniki/Kontrola) pochodzą wyłącznie z komentarzy w migracjach i z dwóch plików `.docx`. Oznaczone jako „wg komentarza”.
- Treści plików `supabase/tests/*.test.sql` i `tests/**` nie czytano w całości — korzystano z nagłówków (`payout_correctness.test.sql:1-31`) i listy plików. Nie twierdzę więc, że dany niezmiennik „nie ma testu”, tylko jak jest egzekwowany w kodzie produkcyjnym.
- Serwisy `src/lib/services/{employees,engagements,projects,bonus-config}.ts` przejrzano wyrywkowo (grep po regułach, nie lektura liniowa).
- `idea-notes.md` jest pusty (0 linii) — nie jest źródłem.

### Stack i warstwy (gdzie żyje logika)

Astro 7 SSR + React 19 + Supabase (Postgres + Auth + Edge Functions) na Cloudflare Workers (`context/foundation/tech-stack.md:22-39`, `CLAUDE.md` sekcja Architecture).

| Warstwa                   | Ścieżka                                                                | Co tu mieszka                                                                                                                                                                |
| ------------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Persystencja + **domena** | `supabase/migrations/`                                                 | CHECK-i, triggery strażnicze (kody `MR001…MR015`), RLS, funkcje liczące (`kpi_multiplier`, `capped_payout_pool`, `milestone_payout_lines`, `approve_milestone`), widoki flag |
| Funkcje Edge              | `supabase/functions/{invite-employee,notify-milestone-approved}`       | zaproszenia i e-maile (jedyny kod z kluczem secret)                                                                                                                          |
| Serwisy                   | `src/lib/services/*.ts`                                                | zapytania, mapowanie błędów SQLSTATE na komunikaty — **bez** wzoru premii                                                                                                    |
| Czyste helpery            | `src/lib/{dashboard,history,assignments,bonus-report,route-access}.ts` | filtrowanie/sumowanie wyników już ocenionych przez RLS                                                                                                                       |
| API                       | `src/pages/api/**`                                                     | cienkie handlery POST + zod                                                                                                                                                  |
| UI                        | `src/pages/**`, `src/components/**`                                    | `.astro` + wyspy React                                                                                                                                                       |

**Wniosek strukturalny:** wzór premii istnieje w kodzie dokładnie raz — w SQL. Aplikacja TS niczego nie przelicza (patrz `src/types.ts:146-147`: „display them, never recompute them”; `src/lib/services/approvals.ts:291-297` mapuje zamrożony snapshot na kształty Draft). To mocna strona i zarazem powód, dla którego rozjazdy dotyczą głównie _słownika i statusów_, a nie arytmetyki.
