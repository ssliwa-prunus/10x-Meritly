# Observability audit — projects, milestones, employees (2026-10-15)

## 1. TL;DR

- **Mapped means unlogged.** Every service and Edge Function logs only the "unexpected" fall-through. Codes that look expected but also signal a regression are mapped to a user message with no log line: `42501` becomes "not found", `MR014` becomes "score all KPIs", Auth 4xx becomes "email unavailable", and known notify codes become a flash. A grants or RLS migration regression makes approve, KPI save, engagements, project and employee writes answer "Not found" with **zero log lines**.
- **Auth unavailable looks the same as signed out.** `src/middleware.ts:17-20` ignores the `getUser()` error, and `createClient` returns `null` silently when config is missing. A Supabase Auth outage or a missing secret turns every protected request into a normal-looking 302 to sign-in, with nothing logged.
- **Outcomes live only in redirect query params.** Approval commits, then the email outcome (`email_failed`, `email_partial`, `send_failed`, `email_not_configured`) is carried only in `?notice=`. Employees can stay un-notified indefinitely with no trace in Workers Logs (`approve.ts:57-59`).
- **No shared error serializer and no context.** Log lines carry `{code, message}` (or just an error class name for Edge Function failures). `details`, `hint`, HTTP status, response body, user id, entity id and request id are all dropped. A DB network failure logs as `code: ""`.
- **No app boundary.** Astro catches every throw, logs `err.stack` without the cause, returns an empty 500 and never marks the invocation as an exception. Load failures render as 200 and failed writes as 302, so status and outcome metrics never show an outage.
- **Most important consequence:** a broken service key or a grants regression after a deploy silently stops every invite, every approval email or every write in these flows. Users see plausible "Not found" / "Check the email" messages and Workers Logs stays empty.

## 2. Capture model

- **Runtime.** Astro 7.3.2 SSR (`output: "server"`) on Cloudflare Workers via @astrojs/cloudflare 14.3.1 (`wrangler.jsonc` `main`). One React island, `src/components/SubmitButton.tsx`, used only for the pending state. Supabase (PostgREST/RPC with RLS) is called from the Worker with the user's JWT (`src/lib/supabase.ts`). Two Supabase Edge Functions (Deno) are called via `supabase.functions.invoke`: `invite-employee` and `notify-milestone-approved` (Resend in production).
- **Error tracker.** None. `package.json` has no tracker SDK.
- **Logging.**
  - The production signal is Cloudflare Workers Logs (`wrangler.jsonc` `observability.enabled: true`), plus Supabase's own Edge Function logs, which are a separate pipeline.
  - App code logs via raw `console.error` (22 sites in `src`, 15 in `supabase/functions`). There is no logger abstraction.
  - Services log through per-file copies of `mapLoadError` / `mapPostgrestError`, for example `src/lib/services/projects.ts:293-308` and `approvals.ts:192-205`. These log `{ code, message }` only.
- **Capture boundaries.**
  - There is no app boundary: `src/middleware.ts` has no try/catch around `next()`, and there is no `src/pages/500.astro`.
  - Astro catches throws from middleware, pages and endpoints (`node_modules/astro/dist/core/routing/handler.js:101-108`). It logs `"[ERROR] " + err.stack` (no `cause`), returns an empty-body 500, and does not rethrow. The Workers invocation outcome is therefore "ok" with status 500.
  - Errors thrown after streaming starts would bypass Astro's logger and truncate a 200 page. This is latent today, because no component awaits data.
- **Error-to-response convention.**
  - Services return `{ data } | { error: code }`.
  - API routes are POST form handlers that redirect with `?error=` / `?saved=` / `?notice=` (88 `context.redirect(…error…)` sites).
  - Pages render load failures as an `Alert` with status 200.
- **Client side.** There are no global handlers or error boundaries, and no client `fetch`. The risk is low by architecture.
- **Background work.** There is no `waitUntil`. Notification runs synchronously in the request. Edge Function failures are logged only in Supabase. The Worker logs a function failure by error class name only, and logs nothing for known codes.
- **Deploy identity.** Nothing in code: no release or version constant, no `version_metadata` binding, no request id, no environment tag.

**Assumptions (outside the repo, not findings):**

- Workers Logs collects console output and per-invocation metadata (URL, status, outcome) at the default sampling. _Confirmed by user_ ("Workers Logs only").
- No tracker, alert rules or log forwarding exist. _Confirmed by user._
- Supabase Edge Function, Auth and PostgREST logs are retained in the Supabase dashboard, uncorrelated with Workers Logs. _Unconfirmed._
- Production secrets (`SUPABASE_URL`, `SUPABASE_KEY`, `RESEND_API_KEY`, `MAIL_FROM`, `APP_URL`, function service key) are set. _Unconfirmed_: the code makes their absence silent (X3, M1).
- Preview and staging deployments are separated outside the repo. _Unconfirmed._

## 4. Systemic root causes

1. **RC1 — Mapped means unlogged.**
   - **Mechanism:** every error mapper logs only its fall-through. Known codes return before the `console.error`:
     - `src/lib/services/projects.ts:294-298`
     - `src/lib/services/employees.ts:220-223`
     - `src/lib/services/approvals.ts:186-197`
     - `src/lib/services/payouts.ts:170`
     - `src/lib/services/engagements.ts:209`
     - Edge Function code maps: `approvals.ts:407-409` and `employees.ts:378-381`
     - Function-side 4xx branches: `supabase/functions/invite-employee/index.ts:84-86` and `supabase/functions/notify-milestone-approved/index.ts:238,250-253`
   - **Why it exists:** a reasonable privacy and UX decision ("to the caller the project does not exist") and a wish to avoid noise.
   - **The problem:** the same code also covers deploy regressions (missing grant, broken `WITH CHECK`, broken service key, broken claims shape, snapshot invariant breach).
   - **Explains:** X1, E1, M2, M4, P2, P6, E6, E8.
2. **RC2 — Outcomes are encoded in redirect URLs, and status codes never reflect failure.**
   - **Mechanism:**
     - Every write failure is a 302/303 with `?error=` (88 sites).
     - Load failures render 200 (`src/pages/projects/index.astro:39-40,66-70`, `projects/[id].astro:57-59,101-105`).
     - The post-approval email result exists only in `?notice=` (`src/pages/api/projects/[id]/milestones/[milestoneId]/approve.ts:57-59`, `notify.ts:101-107`).
   - **Why it exists:** progressive-enhancement form posts with flash codes.
   - **The problem:** nothing records the outcome server-side.
   - **Explains:** M1, M6, M7, X8, P3, P4, P7.
3. **RC3 — "Auth or config unavailable" is the same as "anonymous".**
   - **Mechanism:**
     - `src/middleware.ts:17-20` reads `data.user` and ignores `error`. auth-js returns network and 5xx failures as a value, `AuthRetryableFetchError` with `user: null`.
     - `src/lib/supabase.ts:6-8` returns `null` on missing env, and the secrets are declared `optional: true`.
     - `src/lib/set-password.ts:75-76` returns `false` on a `getClaims` error.
     - `src/pages/auth/confirm.ts:21-39` redirects every failure to `invite_invalid`.
   - **Explains:** X2, X3, X4, X9, E2, E5, E10.
4. **RC4 — No shared error serializer or context.**
   - **Mechanism:**
     - Each mapper copy hand-picks `{ code, message }`, dropping `details`, `hint` and `status`. That is where postgrest-js puts the network cause and the timeout hint (`postgrest-js/dist/index.mjs:416-455`).
     - Function failures are logged as `{ name }` only (`approvals.ts:413`, `employees.ts:410`).
     - `functionErrorCode` consumes the response body and swallows parse errors (`employees.ts:386-395`).
     - No user, entity or request id is passed in, and nothing correlates Worker logs with Edge Function logs.
   - **Explains:** X5, X6, M3, E3, E4, E7, M5.
5. **RC5 — No app-level boundary.**
   - **Mechanism:** there is no wrapper around `next()` (`src/middleware.ts:76`) and no `500.astro`. Astro's catch (`node_modules/astro/dist/core/routing/handler.js:101-108`) logs `err.stack` only (no `cause`, route, user or release), returns an empty 500 and swallows the throw, so the platform never records an exception.
   - **Explains:** X7, X10.

## 6. Recommended fix order

1. **Shared `logSupabaseError` / `logFunctionError` helper, and log the regression-capable mapped codes.**
   - Closes X1, X5, X6, M3, E4, P6, and partly M4, E6, E8.
   - One helper replaces the per-service mapper copies and is called on the mapped `42501`, `MR014`, `23514` and unknown function-code branches at warn level.
   - **Constraint:** no emails or PII in log payloads; log ids only, and keep the user-facing codes unchanged.
2. **Middleware: treat Auth and config unavailability as an outage, not as anonymous.**
   - Closes X2, X3, X9, E5.
   - Log, then return 503, for a `getUser` error (excluding the missing-session case), for a null client on protected routes, and for a null profile.
   - **Constraint:** keep the anonymous redirect for genuinely missing sessions, so the logs don't fill with normal sign-in traffic.
3. **Approval and notification outcome lines.**
   - Closes M1, M2, M6, M7.
   - `approve.ts` and `notify.ts` log at error level whenever the notice is non-empty.
   - The notify function logs every non-200 and logs partial sends at warn/error.
   - The Worker validates the function body.
4. **Invite pipeline.**
   - Closes E1, E3, E8.
   - Map only `email_exists` / `user_already_exists` to `email_unavailable`.
   - Log every other Auth error with `{employeeId, status, code}`.
   - Include `invitedUserId` in the link-failure log, and add a trigger warning on 0-row activation.
5. **Auth edges.**
   - Closes E2, X4, E10.
   - `/auth/confirm`, sign-in, sign-up and set-password log non-expected errors.
   - **Constraint:** never log tokens or emails.
6. **App boundary and status codes.**
   - Closes X7, X8, P3, P7, and partly X13 (in-stream render errors need the component-level guard).
   - Add a try/catch around `next()` that logs with the cause, route, user and request id, then rethrows. Add `500.astro`. Set 5xx/404 status on page load errors and not-found.
7. **Correlation and context.**
   - Closes E7, X10, X14, M5.
   - Pass `x-request-id` (cf-ray) to Edge Functions; add a `version_metadata` binding; enable `upload_source_maps`; log Resend error bodies.
8. **Local silence detectors.**
   - Closes P2, P4, P5, M8, M9, E9, P8, M11, X11, X12.
   - Add warn lines on 0-row updates, missing exposure rows, empty summaries and dropped embeds; give payout raises custom codes; demote `MR015`.
